# P1.3.1 Scene Continuity & One-Viewport Visual Refinement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the current P1.3 interface into five complete one-viewport scenes, with full outgoing/incoming canvas handoffs, no background-only transition frame, no primary Stepper/trust clutter, and no document scrolling for normal desktop stage content.

**Architecture:** `CompilerDemo` remains the owner of product state, API lifecycle, loading, answers, retrieval, compilation, copy, and navigation. A new `StageTransitionViewport` becomes the only owner of full-scene motion: it snapshots the last stable React node, mounts the incoming node beside it, animates both complete `SceneCanvas` wrappers together, then removes the outgoing snapshot after completion. Stage components keep their existing domain inputs, but Clarify becomes single-question focus and long evidence/details move into bounded internal regions or an overlay rather than increasing document height.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript 5.9, GSAP 3.15, `@gsap/react`, CSS, Vitest, `react-dom/server` static rendering tests.

**Spec:** `docs/superpowers/specs/2026-09-14-p1.3.1-scene-continuity-visual-refinement-design.md`

## Global Constraints

- Do not modify analyze/retrieve/compile API contracts.
- Do not modify DeepSeek/provider behavior.
- Do not modify Domain schemas or five-stage semantics.
- Do not modify Zhihu retrieval, semantic audit/repair, publishable question schema, clipboard formatting, or publishing behavior.
- Keep the existing five scene colors unchanged in this phase.
- Do not add ScrollTrigger, View Transitions API, WebGL, 3D, Companion Extension, or Expo work.
- Desktop target: `Header + Active Scene = 100dvh`.
- 1920×1080 and 1440×900 must show each normal stage’s primary information and primary action without document scrolling.
- 1366×768 must use compact density rather than growing the document.
- Mobile uses the same scene architecture; the document stays fixed to `100dvh`, with only bounded stage-internal regions allowed to scroll when content is intrinsically long.
- Remove the desktop five-step Stepper and the mobile progress card from the primary flow.
- Remove completely, with no replacement badge/helper copy: `真实链路 · AI + 知乎检索`, `真实 AI + 知乎检索`, `只整理与复制问题，不会自动发布`.
- Loading belongs to the current scene. Scene movement begins only after the next stage data is ready.
- Forward navigation: complete outgoing canvas moves left while complete incoming canvas enters from the right.
- Backward navigation: direction reverses.
- There must never be a frame where only a flat stage background is visible.
- Keep the subtle primary headline upward reveal, but it must never hide the full scene content tree.
- GSAP owns full-scene movement and the explicit primary-headline reveal.
- CSS owns hover/press/focus/spinner/small selection feedback.
- React owns business state, data availability, loading, answers, and whether a new target stage exists.
- Prefer `transform` and `opacity`; do not animate scene motion with `width`, `height`, `top`, or `left`.
- `prefers-reduced-motion: reduce` uses a short approximately 160ms full-canvas crossfade or immediate swap.
- Execute from latest `origin/main` in an isolated worktree/temporary branch, recommended branch name `feat/p1.3.1-scene-continuity`.
- Keep repository active branch count within the existing ≤5 rule.
- Every task follows RED → verify RED → minimal GREEN → verify GREEN → focused cleanup → commit.

import { getStageIndex, type QuestionCompilerStage } from "@ask-better/domain";
import type { ReactNode } from "react";

export type SceneTransitionDirection = "forward" | "backward";

export interface SceneSnapshot {
  stage: QuestionCompilerStage;
  content: ReactNode;
}

export interface SceneTransitionPair {
  outgoing: SceneSnapshot;
  incoming: SceneSnapshot;
  direction: SceneTransitionDirection;
}

export function getSceneTransitionDirection(
  from: QuestionCompilerStage,
  to: QuestionCompilerStage
): SceneTransitionDirection {
  return getStageIndex(to) >= getStageIndex(from) ? "forward" : "backward";
}
```

import type { QuestionCompilerStage } from "@ask-better/domain";
import type { CSSProperties, ReactNode } from "react";
import { stageVisuals } from "../lib/stage-visuals";
import { StageBackdrop } from "./stage-backdrop";

export interface SceneCanvasProps {
  stage: QuestionCompilerStage;
  role: "stable" | "outgoing" | "incoming";
  hidden?: boolean;
  children: ReactNode;
}

export function SceneCanvas({ stage, role, hidden = false, children }: SceneCanvasProps) {
  const visual = stageVisuals[stage];
  const style = {
    "--scene-background": visual.background,
    "--scene-foreground": visual.foreground === "light" ? "#FFFFFF" : "#2D2114",
    "--scene-accent": visual.accent,
    "--scene-surface": visual.surface
  } as CSSProperties;

  return (
    <section
      className="scene-canvas"
      data-stage={stage}
      data-scene-role={role}
      aria-hidden={hidden || undefined}
      style={style}
    >
      <StageBackdrop stage={stage} />
      <div className="scene-safe-frame">
        <div className="scene-content">{children}</div>
      </div>
    </section>
  );
}
```

- [ ] **Step 4: Implement stable snapshot behavior in `StageTransitionViewport`**

Use these state/ref responsibilities:

```ts
const rootRef = useRef<HTMLDivElement>(null);
const [displayedStage, setDisplayedStage] = useState(targetStage);
const [pair, setPair] = useState<SceneTransitionPair | null>(null);
const stableSnapshotRef = useRef<SceneSnapshot>({
  stage: targetStage,
  content: scene
});
```

Required behavior:

1. If `pair === null` and `targetStage === displayedStage`, refresh `stableSnapshotRef.current` with the current `scene`. This keeps typing, option selection, loading text, and copy status live while the stage is stable.
2. If `pair === null` and `targetStage !== displayedStage`, create a pair from the previously saved stable snapshot and the new `{ stage: targetStage, content: scene }`.
3. Before the pair is created, render the stable snapshot, not the new target node. This prevents a one-frame target-content flash.
4. While `pair !== null`, render both complete canvases.
5. On animation completion, set the incoming snapshot as stable, set `displayedStage` to the incoming stage, and clear `pair`.

The outgoing snapshot must be a previously rendered ReactNode, not `renderStage(outgoingStage)` recomputed from newly cleared state. This is required so Result can remain visible while `handleReoptimize()` clears later-stage data.

export function findFirstUnansweredIndex(
  questions: ClarificationQuestion[],
  answers: ClarificationAnswers
): number {
  const index = questions.findIndex((question) => !answers[question.id]);
  return index === -1 ? Math.max(questions.length - 1, 0) : index;
