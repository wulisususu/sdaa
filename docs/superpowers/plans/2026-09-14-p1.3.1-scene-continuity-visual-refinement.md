# P1.3.1 Scene Continuity & One-Viewport Visual Refinement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refine the existing P1.3 five-scene Web experience so every stage behaves as a complete one-viewport canvas, adjacent stages hand off as full outgoing/incoming scenes with no background-only flash, and redundant Stepper/trust UI is removed.

**Architecture:** Keep `CompilerDemo` as the owner of business state and API lifecycle. Replace the current single-scene entrance animation with a double-buffered `StageTransitionViewport` that temporarily renders an outgoing `SceneCanvas` and incoming `SceneCanvas` together, animates both wrappers in one GSAP timeline, then discards the outgoing snapshot. Stage-specific components remain responsible for content; layout is compacted to fit the fixed viewport, and overflow-heavy evidence/detail moves into bounded internal regions or overlays instead of growing the document.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript 5.9, GSAP 3.15, `@gsap/react`, CSS/Tailwind base styles, Vitest, React server rendering tests.

**Spec:** `docs/superpowers/specs/2026-09-14-p1.3.1-scene-continuity-visual-refinement-design.md`

## Global Constraints

- Do not modify analyze/retrieve/compile API contracts, DeepSeek provider logic, Domain schemas, Zhihu retrieval, semantic audit/repair, publishable question schema, clipboard formatting, or publishing behavior.
- Keep the existing five scene colors unless separately approved.
- Do not add ScrollTrigger, View Transitions API, WebGL, 3D, Companion Extension, or Expo work.
- Desktop target: `Header + Active Scene = 100dvh`; normal stage content must not require document scrolling at 1920×1080 or 1440×900.
- 1366×768 must use compact density rather than document overflow.
- Mobile uses the same scene architecture; the document stays fixed to `100dvh`, with only bounded stage-internal regions allowed to scroll when unavoidable.
- Remove the large desktop Stepper and mobile progress card from the primary flow.
- Remove completely, without replacement badges/helper copy: `真实链路 · AI + 知乎检索`, `真实 AI + 知乎检索`, `只整理与复制问题，不会自动发布`.
- API loading belongs to the current scene. Do not begin scene movement until the next stage data is ready.
- Forward transition: complete outgoing canvas moves left while complete incoming canvas enters from the right. Backward transition reverses direction.
- Never create a frame where only a flat scene background is visible.
- Preserve the subtle upward headline reveal, but it remains secondary to the full-canvas handoff.
- GSAP owns full-scene movement and headline reveal; CSS owns small hover/press/focus/spinner feedback; React owns business state/data/loading.
- Prefer `transform` and `opacity`; do not animate layout-heavy `width`, `height`, `top`, or `left` for scene motion.
- `prefers-reduced-motion: reduce` uses a short ~160ms crossfade/immediate swap, never a full horizontal travel.
- Execute in an isolated worktree/temporary branch from latest `origin/main`; do not develop in the production worktree. Keep active branch count within the repository’s existing ≤5 branch rule.
- Every task follows RED → GREEN → focused refactor → targeted tests → typecheck where relevant → commit.

- [ ] **Step 3: Implement the pure transition model**

Create `stage-transition-model.ts`:

```ts
import { getStageIndex, type QuestionCompilerStage } from "@ask-better/domain";
import type { ReactNode } from "react";

export type SceneTransitionDirection = "forward" | "backward";

export interface SceneSnapshot {
  stage: QuestionCompilerStage;
  content: ReactNode;
}

export interface SceneTransitionPair {
  outgoing: SceneSnapshot;
  incoming: SceneSnapshot;
  direction: SceneTransitionDirection;
}

export function getSceneTransitionDirection(
  from: QuestionCompilerStage,
  to: QuestionCompilerStage
): SceneTransitionDirection {
  return getStageIndex(to) >= getStageIndex(from) ? "forward" : "backward";
}
```

- [ ] **Step 4: Implement `SceneCanvas` as a non-animating visual layer**

Move the scene CSS-variable calculation out of the old shell into `scene-canvas.tsx`:

```tsx
import type { QuestionCompilerStage } from "@ask-better/domain";
import type { CSSProperties, ReactNode } from "react";
import { stageVisuals } from "../lib/stage-visuals";
import { StageBackdrop } from "./stage-backdrop";

export interface SceneCanvasProps {
  stage: QuestionCompilerStage;
  role: "stable" | "outgoing" | "incoming";
  hidden?: boolean;
  children: ReactNode;
}

export function SceneCanvas({ stage, role, hidden = false, children }: SceneCanvasProps) {
  const visual = stageVisuals[stage];
  const style = {
    "--scene-background": visual.background,
    "--scene-foreground": visual.foreground === "light" ? "#FFFFFF" : "#2D2114",
    "--scene-accent": visual.accent,
    "--scene-surface": visual.surface
  } as CSSProperties;

  return (
    <section
      className="scene-canvas"
      data-stage={stage}
      data-scene-role={role}
      aria-hidden={hidden || undefined}
      style={style}
    >
      <StageBackdrop stage={stage} />
      <div className="scene-safe-frame">
        <div className="scene-content">{children}</div>
      </div>
    </section>
  );
}
```

- [ ] **Step 3: Implement stable-scene snapshot behavior**

`StageTransitionViewport` must keep:

```ts
const [displayedStage, setDisplayedStage] = useState(targetStage);
const stableSnapshotRef = useRef<SceneSnapshot>({ stage: targetStage, content: scene });
const [pair, setPair] = useState<SceneTransitionPair | null>(null);
```

Rules:

1. While idle and `targetStage === displayedStage`, refresh `stableSnapshotRef.current.content = scene` so typing/options/current UI stay live.
2. When `targetStage !== displayedStage`, create:

```ts
{
  outgoing: stableSnapshotRef.current,
  incoming: { stage: targetStage, content: scene },
  direction: getSceneTransitionDirection(displayedStage, targetStage)
}
```

3. Until that pair exists, keep rendering the stable snapshot; never briefly render an empty target scene.
4. While `pair !== null`, render both complete canvases.
5. On complete, set the incoming snapshot as stable, update `displayedStage`, then clear the pair.

- [ ] **Step 4: Implement the GSAP handoff**

Use `useGSAP` scoped to the viewport. Forward baseline:

```ts
const distance = pair.direction === "forward" ? 100 : -100;
const tl = gsap.timeline({ defaults: { ease: "power3.inOut" } });

tl.fromTo(
  outgoing,
  { xPercent: 0 },
  { xPercent: -distance, duration: 0.68 },
  0
);

tl.fromTo(
  incoming,
  { xPercent: distance },
  { xPercent: 0, duration: 0.68 },
  0
);
```

For reduced motion, branch with `gsap.matchMedia()`:

```ts
outgoing: opacity 1 -> 0
incoming: opacity 0 -> 1
duration: motionTokens.reduced // 0.16
```

Critical implementation rules:

- do not set whole incoming scene content to `opacity: 0` during normal motion;
- both canvases start fully painted;
- `outgoing` and `incoming` wrappers use `position:absolute; inset:0`;
- both receive `pointer-events:none` during transition;
- after completion, only the stable scene is interactive;
- cleanup kills/reverts the timeline through scoped GSAP lifecycle.
